What "Pack 3" was

The September audits (portability + surface quality) produced three fix packs. Packs 1–2 were surface iteration mechanics and prompt rewrites. Pack 3 made the runner system-agnostic, for the work-laptop trial and for this workflow:

  • Board providers — trackers (Linear today, Jira later) hand back one neutral issue shape; which column means "go" and what states phases map to is config, not code.
  • Spawn executes the node's command — the command line that launches a session is data in the node registry, so a different agent CLI (or the dialogue task node) is a config edit, not a code change.
  • Hardcoded edges became config — summon token, skill requirements, status page bind, event paths.

It landed Sept 17 (with one startup regression, fixed same hour) and the daemon is running on it. This dialogue workflow sits directly on the spawn seam, which is why round 1 wanted Pack 3 first.

The design, as it now stands

  • Workflow #3 (config/actions-dialogue.json): task event → spawn a generic task node that does the work and authors its result as a surface; your surface feedback → resume the same session with your annotations as the next turn; approve → done or chain. No GitHub involved anywhere.
  • Quick lane (new): inline surface buttons dispatch one-off cheap agents for lookups and small questions; the answer renders into the page without a full round.
  • Entry (reframed): the statusd page becomes the agent-manager home — open agents grouped by project/story, finished ones bubble up, a new-task form on top. CLI underneath.
  • HITL hardening (proposed as its own round): a shared surface-runtime package every page loads (session binding, queuePrompt, render guarantees — fixes the CLI/MCP disjointedness) and token-gated serving so the surface backend isn't open to iframe injection.
