System audit & iteration plan

cadre-runner · true-prototype · two audits (portability + driver-surface quality) · 2026-09-16

TLDR: The system ports to GHES+Jira with 2 real fixes and a config pass — nothing structural. The driver surfaces have one near-solid gate (spec review) and one broken one (iteration/interrogation: rounds overwrite each other, your annotation anchors are discarded, replies never come back to the page). 4 decisions below; the fix work itself is small and ordered.

Audit 1 — portability (GHES + Jira)

Done already: GitHub transport rides the gh CLI; host is GH_HOST. Repo is public.

Two real gaps:

  • Board seam is a facade. No provider interface — pipeline.py consumes raw Linear payloads and hardcodes state names ("In Progress"). A Jira provider would have to impersonate Linear. Fix: neutral issue dict + state maps to config, then JiraBoard is one clean module.
  • "Agent command is node data" is false at the spawn seam. The engine computes the node's argv from the registry — and runs.py discards it, re-deriving hardcoded claude flags. Swapping in codex today silently wouldn't work. Fix: spawn executes the node's argv.
Config-ify list (each small)
  • @claude summon token (poller.py) — corporate bot account will differ
  • skills-source path hard-fails if the private dev-config tree is absent — install blocker on a fresh laptop
  • statusd binds 0.0.0.0:8181 and ignores configured data_dir; board_events same drift
  • surface health URL hardcodes 127.0.0.1:4387 while statusd honors the env var — they can disagree
  • no systemd/service files ship; branch + PR-title grammar not configurable (fine until a repo policy objects)

Audit 2 — driver-surface quality

Graded against your bar: full understanding, minimum reading time, good iteration, risk stops that explain the risk, PR review that shows the code.

  • Spec review (gate a): closest to the bar. The prompt already demands a briefing-not-a-copy with an annotated file tree. Gaps: driver calls buried 5th of 6, never says what approval commits to, no length budget, alternatives-rejected only implicit.
  • Interrogation (gate b): broken, structurally. All spec-stage sessions share one artifact path, so round N destroys round N−1 — "what changed since your feedback" is unimplementable. The interrogate/revise prompts never mention the surface at all. Your annotations lose their anchors (selector discarded, text kept). Replies go to GitHub only — the surface collects your feedback and never shows the response.
  • Risk hold (gate c): best-specified prompt (decision brief with evidence and recommendation) but shows zero code, never says what approving commits to, and its "Reject — send back" button actually just parks the PR (label + comment, no revise round).
  • Final review (gate d): ambitious, wrong center of gravity. Demands proof and curated hotspots, but no review order, residual risks dead last, and it cannot render diffs — the theme has no add/remove styling and sessions are banned from own CSS. Final-state snippets hide the change under review.
  • Measurement gap: the briefing judge covers gate (a) only, and scores groundedness, not decision-brief shape. The three weakest gates are the three unmeasured ones.
Where each fix lands

Structural (pipeline.py/surface.py): versioned round artifacts (spec-<slug>-r<N>.html), staleness guard on reopen, anchor preservation, replies rendered back onto the page, a diff primitive in the theme. Prompt-level (registry versions, promotable/revertible): BLUF ordering + "what approval commits to" on spec review; what-changed-first pages with quoted driver points on interrogate/revise; evidence hunks + likelihood×impact scale + honest button copy on risk; review order + before/after hunks + risks-after-demo on final review. Judge rubrics for gates b/c/d ride the existing harness.

Proposed order

  1. Pack 1 — surface structure: round versioning, staleness guard, anchors, replies-on-page, diff styling in the theme. Unblocks everything prompt-level.
  2. Pack 2 — prompt pack: the four gates' instruction edits, shipped as new registry versions; judge rubrics for the unmeasured gates.
  3. Pack 3 — portability: spawn-seam argv fix, board normalization + JiraBoard seam, the config-ify list.
  4. Testbed loop: run real tickets, you grade surfaces, edits fold back via the registry.

Both audit reports get committed under docs/audits/ as part of pack execution.
