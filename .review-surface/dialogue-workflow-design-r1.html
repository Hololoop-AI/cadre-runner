Dialogue workflow — sessions over the surface

cadre-runner · design proposal · 2026-09-17

Orientation: You asked to replace interactive terminal sessions with headless claude -p runs orchestrated by the board, where the review surface is the only channel: the board feeds your surface feedback back into the session or advances it past an approval gate. This page is the design for that as workflow #3 on the existing engine — no engine changes needed — plus the four decisions that shape it.

What already exists vs what's new

Exists: the engine runs any workflow given as an actions config (proven by pipeline + eval configs on one tick). Sessions already park on questions and revive with answers; runs support --resume, so a round can continue the same session with its context intact rather than restarting cold. Surfaces already carry feedback with anchors, and rounds now archive (-r<N>).

New: a config/actions-dialogue.json with three actions and one node:

  • task-requested → spawn task node — a generic node whose prompt is: do the task, then author your result as a surface via auto-surface, ending with an approve/continue form.
  • surface-feedback → resume task — your annotations become the next turn; the session resumes (not restarts) with the feedback and rewrites the surface as a new round.
  • approve → done (or dispatch the next task in a chain). Round caps and escalation ride the existing machinery.

Notably, this workflow needs no GitHub at all — board + surfaces + sessions only. Running it is itself the strongest agnosticism proof yet.

What it costs (the honest part)

  • Turn latency. A terminal exchange is seconds; a surface round is poll-tick + session resume + page rewrite — think ~1-3 minutes per exchange even when healthy. Fine for real work items; heavy for "quick question" traffic. Worth deciding whether an escape hatch stays.
  • Local daemon + permissions. This runs a runner instance on your main machine, spawning sessions with --dangerously-skip-permissions in whatever directory the task targets. On the throwaway repo that was free risk; on your home directory it is not. The design needs a per-task working-directory allowlist in config before full cutover.
  • Cutover reality. The surface panel becomes your inbox: statusd page listing open sessions/surfaces is the "UI". Until that's comfortable, terminal remains the fallback — cutover should be earned, not declared.
