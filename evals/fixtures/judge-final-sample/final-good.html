Residual risks

1. Tag case is normalised on write but not on read. normalize_tag() lowercases on add, so --tag Errand stores errand; but notes list --tag Errand compares raw and prints nothing. Nobody hits this in the transcript because every command there used lowercase. It is a two-line fix and I did not take it: it is behaviour this story never specified, and it belongs in the follow-up that also settles notes search --tag.

2. Ordering is inherited, not asserted at the boundary. The filtered list is id-ordered because the underlying listing is; nothing in cli.py sorts. If the listing ever changes its order, criterion 2 breaks silently — the test asserts the filtered rows, not their order relative to a reordered store.
