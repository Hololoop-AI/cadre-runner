## 1. Plumbing (prerequisites — everything else is cheap once these exist)

- **Artifact archive per run.** Persist every stage's artifacts keyed by run_id + stage.
  Judges and the optimizer then run on *stored* artifacts — iteration costs judge
  tokens, not $25–35 pipeline runs. Replay also removes upstream variance from paired
  comparisons (PROTEA pattern; our `run_spec_eval.sh` is already this for stage one).
- **OTel spans** story → stage → claude call; attributes: run_id, story, stage, cost,
  tokens, verdicts. Own attribute schema (OTel GenAI semconv still unstable).
- **Langfuse self-hosted** (Postgres + ClickHouse + Redis compose; CI deployment per
  driver). Scores API receives judge verdicts and driver labels.
- **Surface label toggle.** One control added to each gate surface: "would you have
  accepted this artifact unedited?" — one click per gate, the calibration label the
  judge program runs on. Annotations already flow; only the writeback to Langfuse is new.

## 2. Judges (build order)

Per-criterion binary PASS/FAIL/UNKNOWN, isolated call per criterion group, **verbatim
quote required as evidence** — extraction against supplied references, never "is this
good". Criteria typed mandatory/important. Judge tier ≠ generator tier. Judged claims
are a second claim kind in the existing `expected.json` schema; `scoring.py`/`stats.py`
interfaces unchanged. Rubric tables: research report §5.3.

1. **Spec briefing groundedness & sufficiency** (7 criteria) — upstream of everything;
   structure checks can't see whether the briefing describes its story.
2. **Risk grade justification** (6 diff-anchored criteria) — the only judgment with
   merge authority. Risk-triage gets **no judge**: scored as precision/recall against
   driver adjudication (a counter).
3. **Demonstration faithfulness** (6 criteria) — every claimed behavior tied to a
   passing test or shown artifact; every done-criterion addressed or reported unmet.

Not judged (deterministic stays deterministic): test pass/red-first, locked-file
modification, spec structure, blast-radius detection (globs feed the judge as
reference), cost/tokens, world-boundary leakage, prose style.

## 3. Calibration

- ~20 **seeded corruptions** of accepted artifacts (delete a constraint, invent a file,
  downgrade a risk grade with a migration present…) — manufactures the fail class and
  measures self-preference directly.
- One ~30-min driver sitting: 15 shuffled artifacts, pass/fail + one-sentence critique.
  ~32 ground-truth items total; under-powered and said so.
- Report per criterion: **Cohen's κ (headline)**, TPR, TNR, UNKNOWN rate; ≥3 runs at
  temp 0. Kill any criterion with κ < ~0.4.
- Ongoing: every judge/driver disagreement at a gate auto-joins the calibration set
  (Cursor Bugbot pattern).
- **Post-optimization re-validation**: after any optimizer round, re-check judge
  TPR/TNR on fresh driver labels. (Documented nowhere in the field; the self-play
  result — judge pass rate 0.72→0.94 while true accuracy stayed 0.20 — is why.)

## 5. Improvement loop (the meta-agent node)

**Trigger**: eval run completes → verdicts land → delta-vs-baseline check fires a
reflection stage the same way risk-high fires risk-triage today.

**Prompt registry (driver decision 2026-09-04: no PRs — prompts are system state,
not code).** Prompts move out of the codebase into a versioned registry owned by the
runner: content-addressed versions + lineage metadata (parent version, what produced
it — hand edit / reflection stage / optimizer round, eval scores per fixture suite,
model pinning) in the data dir, with a **git-backed export** for portability
(transfer to teammates, use outside the system). Every stage run records the prompt
version it ran — provenance for paired A/B comes free. Optional sync to Langfuse
prompt management for the UI (it has versioning, labels, rollback, trace linking);
the runner never depends on it. Long-term this registry IS the skill-registry vision:
entries with attached eval evidence are what makes skills addable and shareable, and
workflow-level entries (a manifest of stage-prompt versions) are how alternative
workflows get generated later.

**Reflection stage**: receives failing criteria + evidence quotes + archived
artifacts; writes a **new candidate version into the registry** — never mutates the
active one. Promotion candidate → active is the gate: auto-promote when the adoption
gate passes and the delta is small; author a short promotion surface (diff, scores,
what the optimizer was reacting to) for anything bigger. Surface decision, not PR
review — same guard, minutes not a review cycle.

**Phased, per the research (all numbers from the report):**
- **Phase 0 (~$20–60): measure first.** Metric noise across repeated identical runs;
  seed headroom via one hand-written variant. If noise ≥ hoped-for effect, stop —
  no optimizer helps. Gains track seed headroom, not search budget.
- **Phase 1 (~$30–80): hand metaprompt loop**, 3–5 iterations of judge-critique →
  prompt-editor → re-eval on replayed artifacts. GEPA's own greedy ablation gets
  about half the Pareto lift for ~2% of the cost.
- **Phase 2 ($250–400/round): `gepa.optimize_anything`** only if Phase 1 plateaus
  below demonstrated headroom. Skip DSPy (adapter parsing taxes `claude -p` prose).
  GEPA drives `claude -p` via subprocess natively ("Using Claude Code as a Proposer").
  Generator haiku/sonnet, reflection opus; cheap-model-optimize-then-transfer is
  published (GEPA Obs. 6) and matches our July gskill result. Optimize a fenced block
  of `prompts/intake.md` first — replay harness exists, no upstream to archive, spec
  errors are the most expensive downstream.

**Post-judge adversarial review (driver addition 2026-09-06, anti-overfitting):**
before any candidate promotes, a fresh session on a *different tier* than both the
generator and the judge attempts to REFUTE the win: hunt judge-exploitation
signatures (length inflation, self-praise phrasing, rubric-keyed wording,
fixture-specific overfit), argue the null (metric noise / seed headroom), and
verdict refuted/stands with evidence. A refutation blocks auto-promotion and
forces a promotion surface. Cross-family pass (e.g. via work Bedrock models) is
the stronger version when available; cross-tier is the floor.

**Adoption gate** (all must hold, else keep the seed — "no adoption" is normal):
beats seed on frozen split under paired McNemar (mid-P); survives BH-FDR across
candidates; no judge TPR/TNR degradation on fresh labels; survives one end-to-end
run; diff contains no fixture-specific nouns; hard fail on any deterministic-claim
regression or any seeded-corruption pass. Length penalty in the metric (measured
exploit: 14.7× length inflation scoring higher).
